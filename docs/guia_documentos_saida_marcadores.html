Marcadores nos Documentos de Saída

Como pôr dados variáveis no texto de um Documento de Saída (Configuração → Documentos Output) e preenchê-los a partir do código — Ordens de Serviço, Declarações ou qualquer documento novo.

Em resumo: escreve-se o texto com ${nome} onde deve entrar um dado; no código monta-se um Map com os valores (vindos de onde quiser: BD, cálculo, texto fixo) e chama-se DocumentoSaidaRenderer.render(tipoDocumento, valores). O motor troca os marcadores no título, no corpo e no "Assinado por".

1. Escrever o texto

No ecrã Documentos de Saída (ou pela API configuracao/documentos-output), o título, o corpo e o "Assinado por" aceitam marcadores:

Escreve no textoSai no documento
${nomeColaborador}O valor de "nomeColaborador" no mapa.
${dataReuniao:-a definir}O valor, ou "a definir" se não for passado (valor por defeito).
${cargo} sem valor— (travessão). Fica um aviso no log com o nome do marcador.
$${nome}O texto literal ${nome} (para escrever um marcador sem o substituir).

Os nomes aceitam letras, números, _ e . (ex.: ${morada.cidade}). Um valor null ou só com espaços conta como "sem valor".

Exemplo de corpo:

Declara-se que ${nomeColaborador}, ${cargo}, pertence ao quadro desta Instituição e aufere o
vencimento ilíquido mensal de ${vencimento} (${vencimentoPorExtenso}).
A reunião realiza-se a ${dataReuniao:-a definir}.

2. Preencher os valores no código

Injete cv.inps.rh.shared.domain.service.documento.DocumentoSaidaRenderer e passe o tipo do documento (o valor de RH_T_PARAM_DOC_OUTPUT.TIPO_DOCUMENTO) e o mapa de valores:

@Service
@RequiredArgsConstructor
public class MinhaDeclaracaoService {

  private final DocumentoSaidaRenderer renderer;
  private final PdfGenerator pdfGenerator;

  public byte[] gerar(FuncionarioEntity funcionario) {
    // 1. Os valores vêm de onde for preciso: BD, cálculo, texto fixo…
    var valores = new HashMap<String, Object>();
    valores.put("nomeColaborador", funcionario.getNome());
    valores.put("cargo", cargoDoColaborador(funcionario));            // null → sai "—"
    valores.put("vencimento", "134 600 CVE");
    valores.put("vencimentoPorExtenso", ValorPorExtenso.escudos(new BigDecimal("134600")));

    // 2. O motor carrega o documento ATIVO do tipo e troca os marcadores
    DocumentoRenderizado doc = renderer.render("CREDITO_HABITACAO", valores);

    // 3. Usar o resultado num template (ver secção 3)
    return pdfGenerator.generate("declaracao/declaracao_credito_habitacao",
        Map.of("param", doc, "watermark", false));
  }
}

O que vem em DocumentoRenderizado

GetterConteúdo
getTitulo()Título com os marcadores trocados.
getCorpo()Corpo com os valores tal como foram passados — para templates que imprimem com th:text.
getCorpoHtml()Corpo com os valores escapados para HTML (&, <, >, aspas) — para templates com th:utext. O texto do corpo em si não é tocado (pode ter HTML próprio) e os acentos ficam como estão.
getAssinadoPor()"Assinado por" com os marcadores trocados.
getResponsavel()Nome do responsável configurado no documento (ou null).
getMarcadoresEmFalta()Marcadores que não tinham valor nem valor por defeito (saíram como "—").

Outras operações do motor

MétodoPara quê
render(tipo, valores)Uso normal. Marcador sem valor → "—" + aviso no log. Nunca bloqueia o documento.
renderEstrito(tipo, valores)Igual, mas um marcador sem valor dá 400 com a lista dos que faltam. Usar quando o documento não pode sair incompleto.
render(entity, valores)Renderiza um ParamDocOutputEntity já carregado (ex.: uma versão que ainda não está ativa).
marcadores(tipo)Lista os ${…} que o texto ativo usa — para saber que chaves preencher.
MarcadoresTexto.substituir(texto, valores, html, emFalta)Só a substituição, sobre um texto qualquer (sem BD, sem Spring). Útil em testes.

3. Usar o resultado num template

O DocumentoRenderizado tem getters, por isso entra diretamente no Thymeleaf:

<h1 th:text="${param.titulo}">Declaração</h1>
<p th:text="${param.corpo}">texto</p>                 <!-- th:text  → getCorpo()     -->
<div th:utext="${conteudo}"></div>                     <!-- th:utext → getCorpoHtml() -->
<strong th:text="${param.assinadoPor}"></strong>
Com th:utext use sempre getCorpoHtml(): com getCorpo() um valor como "João & Filhos" ou "<Lda>" partia o HTML do PDF.

4. Onde já está ligado

DocumentoQuem monta os valoresValores disponíveis
Ordens de Serviço (10 tipos) Um OrdemServicoProvider por tipo em shared/domain/service/ordemservico/ (buildVariables(funcionarioId)); OrdemServicoService.renderizar(tipo, funcionarioId) chama o motor. Os do provider do tipo (ex.: Transferência: nomeColaborador, cargo, escalao, direcao, seccao, ilha, dataEfeito). Para acrescentar um dado: acrescentá-lo ao vars(…) do provider e usá-lo no texto.
Declarações (PDF do Pedido de Declaração) DeclaracaoReportServiceImpl.valoresBase(declaracao) nomeColaborador, nif, cargo, categoria, carreira, vinculo, direcao, seccao, finalidade (descrição), entidadeDestinatario, dataPedido e dataEmissao (por extenso).

Os textos das declarações que estão hoje na BD ainda têm "XXXXXXXX" escrito à mão: basta trocá-los pelos marcadores acima.

5. Testar sem gerar o documento

Dois endpoints no mesmo controller dos Documentos de Saída (configuracao/documentos-output, sem api/v1):

Que marcadores tem um documento

GET configuracao/documentos-output/{uuid}/marcadores

200 → { "tipoDocumento": "TRANSFERENCIA",
        "marcadores": ["nomeColaborador", "cargo", "escalao", "direcao", "seccao", "ilha", "dataEfeito"] }

Pré-visualizar (não grava nada)

Sem corpo usa o documento ativo do tipoDocumento; com corpo usa o texto enviado (para experimentar um texto antes de o gravar).

POST configuracao/documentos-output/pre-visualizar
{
  "tipoDocumento": "TRANSFERENCIA",
  "valores": { "nomeColaborador": "Ana Lima", "cargo": "Técnica", "ilha": "Santiago" }
}

200 → { "titulo": "Transferência",
        "corpo": "… é transferido o colaborador Ana Lima, Técnica —, da — - —, para a Ilha de Santiago …",
        "corpoHtml": "…", "assinadoPor": "Djon Doe", "responsavel": null,
        "marcadoresEmFalta": ["escalao", "direcao", "seccao", "dataEfeito"] }

Sem tipoDocumento nem corpo → 400; tipo sem documento ativo → 404.

6. Passo a passo para um documento novo

  1. Criar o tipo no domínio ORDEM_SERVICO_DECLARACAO (o combo "Tipo de Documento" vem dele).
  2. Registar o Documento de Saída desse tipo com o texto e os marcadores ${…} que precisar. Só pode haver um documento ativo por tipo.
  3. No código, montar o mapa com uma chave por marcador e chamar renderer.render(tipo, valores) (ou renderEstrito se nada pode faltar).
  4. Passar o DocumentoRenderizado ao template (getCorpo() com th:text, getCorpoHtml() com th:utext).
  5. Confirmar com GET …/{uuid}/marcadores e POST …/pre-visualizar que todas as chaves são preenchidas (marcadoresEmFalta vazio).

7. Regras a saber

  • Editar um Documento de Saída cria uma versão nova e inativa a anterior — o motor usa sempre a ativa.
  • O valor é convertido com String.valueOf: formate datas e números antes de os pôr no mapa (ex.: DateFormatter.EXTENDED_DATE_PT dá "23 de outubro de 2026").
  • Um marcador escrito mal no texto (ex.: ${nomeColaboradr}) sai como "—" e aparece em marcadoresEmFalta e no log — é a forma de o detetar.
  • Código: shared/domain/service/documento/ (DocumentoSaidaRenderer, DocumentoRenderizado, MarcadoresTexto); testes em MarcadoresTextoTest.
