validate — hoje falha

O arranque com ddl-auto=validate seria recusado

O validate só verifica a existência de tabelas, colunas e sequências e a compatibilidade dos tipos. Pára no primeiro erro, mas hoje há estes bloqueios:

    update — não ligar

    O ddl-auto=update “corrigia” a BD para o lado errado

    Criaria as tabelas e colunas que o código espera em vez de alinhar o código com a BD, acrescentaria foreign keys que a BD nunca teve e não corrigiria nenhum dos tipos. O script completo está na secção O que o update faria.

    recomendação

    Alinhar as entities e depois ligar o validate

    Corrigir primeiro os itens vermelhos deste relatório (a maioria é um bug real na app) e só então ligar o validate em dev, como verificação só de leitura. O update deve continuar desligado em todos os ambientes; o esquema muda por SQL revisto.

    Tipos incompatíveis

    A família do tipo JDBC difere da coluna real, segundo a regra Dialect.equivalentTypes do Hibernate 6.6: números, vírgulas flutuantes e varchar só são equivalentes dentro da mesma família, e CHAR não é VARCHAR. Em runtime a maioria funciona por conversão implícita do Oracle, mas o validate recusa-os.

    Relação na entity sem foreign key na BD

    Com o update ligado, o Hibernate tentaria criar cada uma destas FKs; se houver linhas órfãs, o ALTER falha e fica só um aviso no log. Para a entity refletir a BD tal como está, o @JoinColumn leva foreignKey = @ForeignKey(ConstraintMode.NO_CONSTRAINT).
